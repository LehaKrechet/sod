# ПО «Сод» — децентрализованный UDP Multicast

Учебный прототип P2P-обмена для Linux. Все экземпляры программы равноправны:
каждый узел обнаруживает соседей, инициирует собственные циклы и отвечает
на запросы других узлов. Центрального сервера или координатора нет.

## Состав

- `src/main.cpp` — сетевой узел, протокол, измерение и терминальная диаграмма.
- `Makefile` — сборка.
- `run.sh` — запуск с параметрами по умолчанию.

## Сборка

Нужны Linux, g++ с поддержкой C++17 и GNU Make:

```bash
sudo apt update
sudo apt install build-essential
make
```

## Запуск

На каждом компьютере в одной локальной сети:

```bash
./sod
```

Если нужный интерфейс имеет адрес `192.168.1.20`:

```bash
./sod --iface 192.168.1.20
```

На всех компьютерах должны совпадать multicast-группа и UDP-порт.
Например:

```bash
./sod --group 239.0.0.1 --port 5000 --iface 192.168.1.20
```

Узнать адреса интерфейсов:

```bash
ip -br addr
```

Остановить: `Ctrl+C`.

## Протокол

- UDP Multicast `239.0.0.1:5000` используется для heartbeat, запросов и ответов.
- Каждый узел отправляет heartbeat раз в секунду.
- Каждый узел периодически отправляет REQUEST со значением `1`.
- Получатель выполняет тестовую операцию `1 + 1` и отправляет RESPONSE
  multicast-группе с идентификатором исходного узла и номером цикла.
- Инициатор измеряет время от отправки запроса до получения ответов от всех
  известных активных соседей (либо до истечения 200 мкс).
- Узел считается активным, если от него было сообщение за последние 3 секунды.

## Что показывает монитор

- длительность последнего цикла;
- среднее, минимальное и максимальное время по окну последних 80 циклов;
- количество циклов, превысивших 200 мкс;
- циклы, в которых не получены ответы от всех известных соседей;
- обнаруженные узлы;
- простую текстовую диаграмму времени последних циклов.

## Важные ограничения и корректная интерпретация 200 мкс

200 мкс здесь — измеряемый целевой порог, а не гарантированная характеристика.
Обычный Linux, планировщик ОС, драйвер сетевой карты, коммутатор и загрузка
сети могут приводить к превышениям. Для строгого real-time результата могут
понадобиться PREEMPT_RT, настройка CPU affinity, приоритетов потоков,
IRQ affinity и специализированный сетевой стенд.

Измерение включает время от отправки multicast-запроса до получения ответов
от всех соседей, известных узлу на начало цикла. При отсутствии соседей
измеряется локальный интервал отправки. Это не является гарантией, что
каждый узел получил каждый пакет: UDP Multicast не гарантирует доставку.
Счётчик таймаутов показывает циклы без полного набора ответов, но не
выявляет все возможные потери heartbeat или дубли.

Для корректного тестирования:
1. Используйте проводной Ethernet и один L2-сегмент/VLAN.
2. Разрешите UDP-порт 5000 в firewall.
3. Убедитесь, что коммутатор и сеть пропускают IPv4 Multicast.
4. Запустите программу минимум на двух узлах.
5. Сравнивайте результаты при одинаковом числе узлов и нагрузке.

## Безопасность

Протокол учебный и не содержит аутентификации или шифрования. Не используйте
его в недоверенной сети или как основу промышленной системы без доработки.
